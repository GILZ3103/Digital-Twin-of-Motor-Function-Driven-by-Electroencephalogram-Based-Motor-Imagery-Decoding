0How to use this brief

  1. Make an empty project folder, for example elbow-twin.
  2. Save this page into it as docs/elbow-intent-build-brief.html.
  3. Open Claude Code in that folder and paste the start prompt below. Fill in your Python version first.
  4. Claude Code works one milestone at a time (section 14) and asks you at every open decision (section 15).

1Hard rules

These rules apply to every line of code. Safety comes first.

Safety

  1. The supervisor decides. Decoders, the intent estimator and the LLM only propose.
  2. No AI in the fast loop. The LLM works only between attempts, never in the 4 ms or 40 ms loops.
  3. During an attempt, signals can only reduce help (rule R6). Nothing raises motor help in the middle of an attempt.
  4. Hard limits live in the microcontroller and the mechanics. The laptop cannot change them while running.
  5. The system must work with the LLM off. Losing the LLM never changes motor behaviour.
  6. The motor is off during calibration.
  7. Simulation first. Every fault has an automatic scenario test before any person wears the device.
  8. Any change to a limit, rule or threshold needs the operator's confirmation and is written to the log.

Data and honesty

  1. Only summaries leave the computer. No raw EEG or EMG, no names, no video. Use coded IDs such as P01.
  2. Every LLM call is logged with the model ID, prompt, response and time. The model version is pinned.
  3. Synthetic signals prove the software, not the decoding. Real accuracy comes only from real recordings.
  4. Recordings stay out of Git. recordings/ is in .gitignore.
  5. The intended arm is a model of intent, not a reading of the brain. Name it that way in code, on screen and in the report.

Out of scope for Claude Code

Firmware, motor drivers, electrode hardware, the clinical protocol and anything that touches a real person. The hardware teammate owns the hardware and signal acquisition.

2The project

The twin shows two elbows side by side. The intended arm is built from EEG on the scalp and EMG on the arm. The actual arm comes from the encoder on a motor-assisted arm brace. The gap (intended minus actual) shows where the person reaches their limit, and it gates assist-as-needed motor help.

Scope now

One degree of freedom: elbow flexion. Software only, with simulated signals. Healthy volunteers come next.

Final users

People in rehabilitation after a stroke. This needs a clinical partner and hospital ethics approval, so it is likely after this project.

Owner

Gilbert does the software. A teammate does the hardware and signal acquisition, discussed separately.

Digital twin level

The twin runs beside the real arm and predicts how it should move (Kritzinger 2018 levels: model, shadow, twin).

The FYP plan also uses "causal twin" for the real-time copy of the preprocessing pipeline. That is a different thing. Keep the two names apart in code and in the report.

Code pattern: logic first, connect later

  • Each core part is a plain Python class with a step() method. Numbers go in, numbers come out.
  • The core does not know about LSL, windows or hardware.
  • An adapter is a short program: it reads LSL, calls step() and writes LSL.
  • Tests call the core directly. A full simulated session runs in a few seconds, faster than real time.

4Intent backbone

Four sources of evidence feed fast learned decoders and an intent estimator. The estimator drives the intended arm and gives the supervisor a calibrated probability. The LLM advisor only adjusts settings between attempts.

The encoder and context arrows pass beside the decoder boxes and go straight into the estimator.

Phases

We start with three phases. Prepare and hold come later, once real EEG shows the rhythm drop before the EMG starts. Agreed

PhaseWhat we expect to seeWhen
RestNo EEG change, quiet EMG, arm stillNow
AttemptEEG mu/beta power drops, EMG rises, the arm moves (or stays still if the person is weak)Now
ReleaseEMG falls, the arm goes downNow
PrepareEEG drop starts about 1–2 s before movement, EMG still quietLater
HoldEMG steady, arm near the targetLater

Evidence and its traps

SourceWhat it addsTrapWhat we do
EEGThe earliest sign of an attemptWeak and noisy. After a stroke the drop can appear on the other side or on both sides.Train per person. Do not tie the decoder to one electrode.
EMGStrong, clear sign of effortLate. After a stroke, biceps and triceps often fire together.Use the biceps–triceps balance, not biceps alone.
Arm encoderShows if the arm movesThe motor also moves the arm.Subtract the motion the motor caused (from the arm model) before counting it as the person's effort.
Task contextAn attempt is more likely just after a cueIf it counts too much, the system sees intent that is not there.Cap its weight. Test with catch trials.

When the quality check marks a signal as bad, the estimator ignores that signal for that step.

Intent estimator spec

  • Model: a hidden Markov model with three states, run as a causal forward filter. It never uses future samples. Agreed
  • Allowed moves: rest→attempt, attempt→release, release→rest, plus staying in the same state. All other moves have probability zero.
  • Inputs per step: calibrated EEG P(attempt) as a logit, log EMG effort, the person's own arm speed (motor part removed), and whether a cue is active.
  • Parameters: learned from calibration data, where the labels are known. Means and spreads per state come from the labelled windows. Move probabilities come from the phase durations.
  • Output: one probability per state, every 40 ms, summing to 1. It must be calibrated: we check expected calibration error (ECE) on held-out trials.
  • Upgrade path: a learned sequence model replaces it only if it beats the HMM on held-out data.
twin/intent_estimator.py (sketch)
import numpy as np

STATES = ("rest", "attempt", "release")

# Moves per 40 ms step. Zero = not allowed. Placeholders: learn them from calibration.
A_DEFAULT = np.array([
    [0.98, 0.02, 0.00],   # rest    -> rest, attempt
    [0.00, 0.97, 0.03],   # attempt -> attempt, release
    [0.05, 0.00, 0.95],   # release -> rest, release
])

class IntentEstimator:
    """Causal HMM forward filter. Numbers in, probabilities out. No LSL here."""

    def __init__(self, A, emissions, cue_boost_max=3.0, cue_cap=0.2):
        self.A = A
        self.em = emissions          # name -> model with .likelihood(x) giving 3 values
        self.cue_boost_max = cue_boost_max
        self.cue_cap = cue_cap
        self.p = np.array([1.0, 0.0, 0.0])

    def step(self, feats, quality_ok, cue_active):
        A = self.A.copy()
        if cue_active:                               # context prior, capped
            A[0, 1] = min(A[0, 1] * self.cue_boost_max, self.cue_cap)
            A[0, 0] = 1.0 - A[0, 1]
        prior = self.p @ A
        like = np.ones(3)
        for name, x in feats.items():
            if quality_ok.get(name, False):          # bad signal: ignore it this step
                like *= self.em[name].likelihood(x)
        post = prior * like
        self.p = post / max(post.sum(), 1e-12)
        return dict(zip(STATES, self.p))

Intended arm

EEG cannot tell us the elbow angle. So the intended arm is built from two things: the phase from the estimator and the effort level from EMG. Agreed

  • When P(attempt) stays at or above 0.70 for 0.15 s placeholder, start a minimum-jerk path from the current intended angle to the target (90° placeholder).
  • The path duration comes from EMG effort, limited to 1.0–3.0 s placeholder. More effort means a faster path.
  • When P(attempt) stays below 0.45 for 0.2 s, or release becomes the most likely state, return to rest with a minimum-jerk path.
  • Gap = intended angle − actual angle. The supervisor and the display use it.
twin/intended_arm.py (sketch)
def min_jerk(theta0, theta1, t, T):
    """Smooth path from theta0 to theta1 over T seconds."""
    s = min(max(t / T, 0.0), 1.0)
    return theta0 + (theta1 - theta0) * s**3 * (10 - 15 * s + 6 * s**2)

5EEG decoder

The decoder answers one question: is this person trying to move now, or resting? It does not read the elbow angle. It looks for ERD: when a person prepares to move the right arm, the 8–30 Hz rhythm over the left motor area gets weaker. Agreed

Grey steps are fixed. The amber step updates every session. Teal steps are trained for each person.

The covariance step in plain words

Think of each electrode as a microphone over a choir. A diagonal cell of the table says how loud one microphone is. An off-diagonal cell says whether two microphones rise and fall together. When the person prepares to move the right arm, the C3 cell drops and C3 stops moving in step with its neighbours, while C4 stays the same. The table is a mirror image, so 8 channels give 36 unique numbers instead of 4,000 raw samples per window.

Three things to watch: artifacts that add power to many channels at once, too few samples for many channels (use shrinkage), and the fact that these tables must not be averaged or subtracted like normal numbers (hence re-centering and the tangent space).

twin/eeg_decoder.py (sketch)
import numpy as np
from pyriemann.estimation import Covariances
from pyriemann.utils.mean import mean_riemann
from pyriemann.utils.base import invsqrtm
from pyriemann.tangentspace import TangentSpace
from sklearn.linear_model import LogisticRegression

cov = Covariances(estimator="oas")            # shrinkage

def recenter(covs, rest_covs):
    """Make today's rest the centre, so the classifier sees change from rest."""
    w = invsqrtm(mean_riemann(rest_covs))
    return w @ covs @ w

# windows: array (n_windows, n_channels, n_samples), already cleaned
C_rest = cov.transform(rest_windows)          # 1-2 min rest, this session
C_cal  = recenter(cov.transform(cal_windows), C_rest)

ts  = TangentSpace(metric="riemann").fit(C_cal)
clf = LogisticRegression(C=1.0, max_iter=1000).fit(ts.transform(C_cal), y_cal)

Training: three kinds

KindWhat it meansPlan
Train per personA small classifier learns from that person's calibration trialsAgreed Main method
Adapt each sessionRe-center to today's rest, plus an optional top-up of 10–20 trialsAgreed
Fine-tune a large modelStart from a model trained on many people (EEGNet or an EEG foundation model), then adjust it with this person's dataDeferred Only if it beats the main method

A model trained on healthy volunteers will not carry over to a stroke patient. Healthy data builds and tests the system; each patient gets their own calibration.

What to expect

Healthy users often reach about 70–85% for rest versus attempt. About 1 in 9 people never get reliable control. Accuracy can fall from 68.8% to 53.7% between sessions and recover to 78.9% with adaptation (figures from the project evidence base). Results after a stroke are lower and vary more. This is why EMG and the estimator are part of the design.

7Rules vs AI study

Movement can be detected without AI. AI mainly adds precision. We turn this into a measured result: run a rules-only detector and the AI detector on the same data and compare them. Agreed

Rules-only detector

EEG: 8–30 Hz power over C3 drops at least 30% below rest for 200 ms placeholder. EMG: the onset rule in section 6. Encoder: the person's own movement. Report each rule alone and combined. It still needs per-person calibration of the rest level and threshold.

AI detector

The EEG decoder (section 5) and EMG features feeding the intent estimator (section 4).

MetricWhy
Share of attempts detectedMisses mean no help when the person tries
False alarms per minute (rest and catch trials)Plain accuracy hides these
Detection delay, relative to EMG onset and movement onsetEEG's main value is an earlier warning
ECE of the probabilitiesThe 0.70 threshold only means something if the probabilities are calibrated

Use a chronological split (train on earlier trials, test on later ones). Never shuffle, because overlapping windows would leak answers into the test. Report results per person.

Rules check the AI, not the other way round

The rules-only detector can also be a plausibility check inside the supervisor. If the AI says "attempt, 0.9" but EMG is silent and the EEG rule sees no drop, the supervisor does not add help and logs the disagreement. Whether EMG agreement is required stays Open: a stroke patient's EMG may be weak exactly when they need help most.

10LLM advisor

A cloud LLM, used between attempts only. It reads a short summary of recent attempts and proposes one typed change. It never reads raw signals, never sets motor force, and never changes limits or rules. Agreed

Plug-in interface

The model is a setting. The cloud is used now with healthy volunteers. If a hospital later does not allow cloud processing, a local model replaces it without changing any other part.

Proposal schema (JSON Schema)

  "type": "object",
  "required": ["action", "reason", "for_attempt"],
  "additionalProperties": false,
  "properties": {
    "action": {"enum": [

}

The supervisor also checks that the resulting start threshold stays within 0.60–0.85 placeholder. There is no action for torque, limits or rules, so the LLM cannot propose them.

Checks before a proposal is used

  1. The output matches the schema. Anything else is rejected and logged.
  2. Every value is inside its bounds.
  3. It is fresh: it targets the next attempt and is under 30 s old placeholder.
  4. The operator approves it. Default: every proposal needs approval. Open The alternative is automatic approval inside a fixed range.
  5. One-click undo returns to the last approved settings.

If the LLM drops

Nothing unsafe happens, because the LLM is not in the control loop.

What goes wrongWhat the system does
No answer within 10 sKeeps current settings, shows "Advisor offline", session continues
Network down for many attemptsSame. RulesAdvisor still flags basic problems such as a bad electrode.
Answer cut off halfwayDiscards it. Never uses part of an answer.
Wrong format or values out of boundsRejects, logs, treats as no advice
Answer arrives after the next attempt startedRejects it as stale
Provider changes or retires the model versionStops using the advisor until the operator approves the new version
Advice looks reasonable but is wrongBounds, operator approval and one-click undo

Privacy

EEG and EMG count as health-related personal data under Malaysia's PDPA 2010. Send only summaries with coded IDs. Use the provider's API, not a chat app, and check its data-retention terms. The university ethics application should state where data goes. Provider choice is Open; any API with structured (JSON schema) output works.

11Display

A desktop screen now. Mixed reality (passthrough headset) later. No full VR, because the person must be able to see their real arm while a motor moves it. Agreed

What the screen shows

  • The actual arm, and the intended arm as a ghost over it
  • The gap in degrees, live and as a trace
  • Phase probabilities (rest, attempt, release)
  • Signal quality per channel
  • Supervisor state, rule hits and motor torque
  • Advisor status (online, offline, proposal waiting for approval) and the operator panel
  • Stop button state

The display only reads streams. Closing it never affects control.

16Questions for the hardware teammate

  • EEG: how many channels, which positions, which amplifier, what sampling rate, and does it publish LSL?
  • EMG: can we sample at 1000 Hz or more, and where do the biceps and triceps electrodes go?
  • Encoder: resolution and update rate. Can the motor current or torque be measured?
  • Can the arm be held still safely for the held-arm calibration block? Mechanical lock or motor hold?
  • Microcontroller contract: are 250 Hz commands, 500 Hz state and a 50 ms heartbeat realistic?
  • For mixed reality later: will a headset strap fit over the EEG cap without pressing on C3 and C4?

17Evidence and standards

Full citations are in the project documents bci-foundations-and-signal-integrity and research-proposal.

  • Hybrid EEG–EMG detection beats EEG alone (91.3% vs 81.8%, Frontiers in Neurorobotics, 2026).
  • Motor attempt beats motor imagery after stroke (79% vs 66.5%, Chen 2021).
  • Continuous kinematics from EEG can be explained by confounds (Antelis 2013). This is why the intended arm is a model of intent.
  • Telling joints of the same arm apart is much harder than detecting move versus rest (Ofner 2017).
  • Abnormal co-activation of elbow muscles after stroke (Dewald and colleagues).
  • Assist-as-needed and slacking (Marchal-Crespo and Reinkensmeyer 2009; Wolbrecht 2008).
  • Digital twin levels (Kritzinger 2018) and human digital twins in rehabilitation (Lauer-Schmaltz 2024).

Standards to follow: ISO 14971 (risk management), IEC 60601-1 and IEC 80601-2-78 (medical electrical equipment, rehabilitation robots), IEC 62304 (medical device software). Data: Malaysia PDPA 2010.

18Terms

ERD
Event-related desynchronization. The 8–30 Hz rhythm over the motor area gets weaker when a person moves or tries to move.
Covariance table
A table of how strong each EEG channel is and how channels rise and fall together.
Re-centering
Measuring EEG change from today's rest, so day-to-day shifts cancel out.
Tangent space
A way to turn covariance tables into normal number lists that a classifier can use.
HMM
Hidden Markov model. Tracks which phase the person is in, using only allowed moves between phases.
ECE
Expected calibration error. Measures whether a stated probability of 0.70 is right about 70% of the time.
Catch trial
A trial with a ready cue where the person is told not to move. It measures false alarms.
Co-activation
Biceps and triceps working at the same time, common after a stroke.
Assist-as-needed
The motor gives only the help the person needs, so they keep trying.
Gap
Intended elbow angle minus actual elbow angle.
LSL
Lab Streaming Layer. Sends data streams between programs with one shared clock.
